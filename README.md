# Lab 001 — Windows Event Investigation

## Overview

This project documents my first beginner Windows security investigation using Windows Event Viewer.

The lab focused on reviewing Windows System and Security logs, identifying important event metadata, collecting evidence, and making a cautious assessment based on the available information.

## Lab Status

- Lab number: 001
- Level: Beginner
- Investigation type: Guided training exercise
- Operating system: Windows 11
- Primary tool: Windows Event Viewer
- Status: Completed

## Objective

The objective of this lab was to learn how Windows records system and security activity and how an analyst can use Event Viewer to examine that activity.

I practiced:

- Navigating Windows Event Viewer
- Reviewing System and Security logs
- Searching for specific Event IDs
- Identifying event metadata
- Collecting screenshots as evidence
- Writing an evidence log
- Building a basic event timeline
- Documenting findings and limitations
- Avoiding conclusions that are not supported by evidence

## Events Reviewed

### Event ID 10016

- Log: System
- Source: DistributedCOM
- Level: Warning

The event showed that Windows recorded a DistributedCOM permission warning.

The warning alone was not sufficient evidence of malware, unauthorized access, or a security incident.

### Event ID 4624

- Log: Security
- Description: An account was successfully logged on
- Relevant security identity: SYSTEM
- Account type observed: Computer account ending with a dollar sign

Event ID 4624 confirms that a successful logon occurred, but it does not automatically prove that a human user logged in.

Successful logon events may be generated by Windows services, applications, scheduled processes, computer accounts, or human users.

## Analyst Assessment

**Classification:** Expected or likely benign system activity

**Confidence:** Moderate

The available account information was most consistent with normal Windows internal activity.

No evidence of malicious activity was identified during this limited investigation.

This assessment only applies to the specific events reviewed. It does not prove that the entire computer was free from malicious activity.

## Main Lesson

A single warning, error, or successful logon event is not enough to declare a cybersecurity incident.

An analyst should review additional context, including:

- Account involved
- Timestamp
- Logon type
- Source computer
- Related events
- Associated processes
- Network activity
- Whether the behavior was expected

Cybersecurity conclusions should be based on evidence, patterns, and context rather than assumptions.
